# 模擬預檢門協議（Gate D 輔助）——預註冊

狀態：**模擬預檢，非五人門**。五人門（[../TRY.md](../TRY.md)）照舊是唯一權威；本協議的全部結果**不得**用於宣稱學習成效或「能讓人講出因果」。TRY.md 的「尚未跑」狀態不因本門改變。

- 任務：EC T-366（人類 2026-09-13「模擬預檢門做」）。
- 產品基準 commit：`c43902f2`（產品 0.6.0／MODEL 1.2.0）。
- 預註冊紀律：本檔的評分準則與測量程序**先於**任何模擬受試者執行寫定；方向表由凍結模型實測（程序見 §4），實測值寫入 §5 後才跑受試者。

## 1. 門的組成

1. **流程冒煙（無 LLM）**：按主持人四步腳本機械走查——開 `loop.html`、按「跟著一顆紅血球」、改一個條件（貧血 +0.30）、等固定窗口、驗證兩側讀數可見差異且 A/B 基線切換可用。這是「參與者走得完流程」的檢查，不通過就不該約人跑五人門。
2. **LLM 模擬受試者（N=5）**：受試者只取得 §2 的主持人四句話與**頁面可見文字**（參數面板、兩側水位、平均負載、分支徽章、字幕），自選一個條件方向，最後產出一句話因果描述。不接觸原始碼、模型欄位名或正確答案。
3. **確定性評分器**：依 §3 評分，無 LLM 判官。

## 2. 主持人腳本（沿 TRY.md 逐字）

1. 打開網址（本機 `http://127.0.0.1:8642/` 或 `loop.html`）。
2. 按「跟著一顆紅血球」，看它走一圈。
3. 自己改一個條件。
4. 看兩邊差在哪，用一句話說「你改了什麼、什麼變了」。

模擬差異（誠實揭露）：受試者以回合制互動——每回合取得當前頁面可見文字，回覆一個動作（改條件／切 A/B／交出最終一句話），上限 6 回合；沒有滑桿連續拖曳，改條件採 §5 的協議增量（單一步，方向 up/down）。畫面是文字轉述（不含動畫與組織色階的視覺觀感），這是代理的侷限。

## 3. 評分準則（預註冊；確定性規則）

先決：受試者實際改的條件與方向由 harness 記錄（`action` 事件），評分比對該記錄，不比對受試者自述的行動名稱。**PASS 必須全部滿足**；任一 FAIL 類別命中即未過：

| # | 檢查 | FAIL 代碼 | 規則 |
|---|---|---|---|
| 1 | 條件可辨識 | `no_condition` / `ambiguous_condition` | 語句中的條件標記（§5 表）恰命中一個已改條件；命中 0 個或命中多個不同條件＝未過 |
| 2 | 方向可辨識 | `no_direction` | 語句含方向標記（拉高/調高/升高/增/提高 ＝ up；拉低/調低/降低/減/壓低 ＝ down） |
| 3 | 行動方向一致 | `direction_mismatch_action` | 語句宣稱的方向 ≠ harness 實際套用的方向 |
| 4 | 結果位置可辨識 | `no_where` | 語句指明哪裡變了：肺泡/肺端（alv）、組織（tis）、平均負載（mean）至少一處 |
| 5 | 效果方向正確 | `reversed_or_wrong_effect` / `claimed_change_where_none` | 對語句指明的每個位置：方向表（§5）預期「變」時，語句方向須同號；方向表預期「≈不變」（|Δ| < 0.01）時，語句不得宣稱該處有變（「沒有改條件的那一側沒有這樣掉」紀律） |
| 6 | 因果連接 | `no_causal_link` | 語句須含行動者/行動詞（我/把/改/拉/調/設）**且**結果詞（變/掉/升/降/少/多/降/升）——只報數值不講因果＝未過 |
| 7 | 非臨床診斷框架 | `clinical_framing` | 語句把觀察講成對真實病人的診斷/處置結論（診斷/確診/病患有/患者有/需要就醫/治療方案）；提及 UI 內的藥物按鈕名稱本身不算 |

嚴格性宣告：標記比對偏嚴——可辨識度不足時判 FAIL（寧可錯殺給人類門留門檻，不放過含糊語句）。這對模擬門是安全方向；代價是可能低估（揭露為侷限）。術語不要求（沿 TRY.md：不要求 load/stock/tick/A/B）。

### 3.1 v1.2 修訂（2026-09-13，第 1 輪計分後、第 2 輪計分前）

第 1 輪（N=5，0/5）逐筆審計發現**量尺與鷹架缺陷**（非受試者能力訊號），修訂如下；第 1 輪紀錄原樣保留並兩輪並報：

- **方向標記擴充（#2/#5）**：v1 標記漏掉自然中文——「設為0.55（比基線低）」未含「拉低/調低」等動詞、「平均負載…降到0.69」的「降到」不在效果標記內。TRY.md 的人類評審會接受這類語句（有條件、有方向、有結果）。擴充為一般化規則：動作方向另認 `比基線低/低於基線`（down）、`比基線高/高於基線`（up）；效果標記另認 `降到/降至/跌到/跌至`（down）、`升到/升至/上升到`（up）。**不**針對特定語句加例外。
- **單一條件約束（harness 鷹架）**：主持人腳本說「自己改一個條件」，v1 harness 未強制（一位受試者連改三個仍被計分）。v1.2 起第二次改條件被拒並提示「你已改過條件」，沿主持人規則。
- **受試者鷹架釐清**：v1 有受試者把藥物按鈕當「條件」（harness 不支援藥物動作；TRY.md 主持人也不會把按藥物當作「改條件」的計分行為）。受試者系統提示釐清「條件＝參數面板滑桿」；此為參與者自身理解範圍的說明，不洩漏任何答案或方向。
- **空回覆處理**：推理模型偶發空內容；空回覆改為一次性輕推（「請輸出你的動作 JSON」），不重複供給畫面（避免變相加時）。

### 3.2 v1.3 修訂（2026-09-13，第 2 輪計分後、第 3 輪計分前；**最終量尺**）

第 2 輪（N=5，0/5）逐筆審計：受試者普遍把**開場暖機暫態**（肺泡 28%→100%、組織水位過衝回升、平均負載 0.17→0.65）誤報為介入效應——他們在 tick 約 200（載入後數秒）就改條件，對比的是「第一眼畫面 vs 現在」。審計結論：訊號為真（快而未觀看的觀察者會把暫態當效應；感染軸宣稱了不可見的效應，評分器正確攔下），但同時暴露 **harness 跳過了主持人腳本第 2 步「看它走一圈」**——v1/v1.2 讓受試者在載入後即時行動，未曾給任何觀看時間。修訂：

- **觀看期（主持人腳本第 2 步的實作）**：harness 在受試者第一次取得畫面前，讓世界至少推進 **600 tick（20 模型秒）**——等同參與者花時間看紅血球走一圈；受試者首次看到的畫面與其後的比較都從這之後開始。
- **效果語彙補完（一般化，非個案）**：第 2 輪語料出現「跳增/暴增/急升」（up）與「急降」（down）等自然語彙，納入效果標記；與 §3.1 同一原則——一般化模式，不針對特定語句。
- **修訂終止宣告**：v1.3 為本預檢門的最終量尺；第 3 輪（含）之後的結果無論高低照實報告，不再修訂量尺或鷹架。第 1、2 輪紀錄原樣保留、三輪並報。

## 4. 方向表測量程序（先於受試者執行）

**v1.1（2026-09-13）**：v1（settle 240 tick＋窗口 240 tick＝8 模型秒、閾值 0.01）在校準時發現兩個測量缺陷——慢軸（貧血／感染／補水／血糖）在 8 模型秒內讀數不動，且 alv/tis 的 DOM 讀數是整數百分比（量化 1%），v1 的 0.01 閾值尺度不符。**v1 測量在任何模擬受試者執行之前作廢**（校準日誌留存於 EC 證據），本 v1.1 為計分前生效版本；窗口與閾值的選擇依據是「參與者在實際觀看時段內、能從讀數上看到的最小變化」，對所有條件一致，不逐條件調整。

**v1.1.1（2026-09-13，緊接 v1.1）**：v1.1 原擬以 UI 4× 速度壓縮牆鐘時間，實測 headless 環境下 4× 會令主線程飽和、tick 凍結（校準日誌留存），故改回 **1×**。速度僅是呈現層（DT＝1/30 模型秒不變），動力學與參與者所見相同；代價是校準牆鐘時間變長，不影響任何測量定義。

- 世界與頁面：`CSL.createWorld({ seed: 7 })`（與頁面同核心）；harness 以頁面 DOM 讀數為準（`#statAlv`／`#statTis`／`#statMean`）。
- 速度：**1×**（v1.1.1；理由如上）。
- 每條件 × 每可用方向一個變體：新鮮世界（種子同 7），settle 240 tick → 對照組（同種子、不改條件）與變體組各在**觀察窗 2400 tick（80 模型秒）**內取 `肺泡水位(statAlv)`／`組織水位(statTis)`／`平均負載(statMean)` 均值 → 差值 Δ。
- ≈不變閾值＝**一個顯示步進**（參與者可見的最小變化）：alv/tis |Δ| < 1.0（整數百分比位）；mean |Δ| < 0.01（兩位小數位）。否則方向：Δ ≥ 閾值記 up，≤ −閾值記 down，其餘記 flat。
- 產出 `direction-table.json`（含 per-condition 實測 Δ 值）；§5 表為其摘要。實測在產品 commit `c43902f2` 上做，方向表綁該 commit；模型升版須重測。
